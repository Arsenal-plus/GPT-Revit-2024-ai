# Revit 2024: реализация аудита

Целевая установленная версия — **24.0.4.427**, `Application.VersionBuild=24.0.4.427`,
метка продукта `20230308_1635(x64)`. Надстройка собирается под **.NET Framework 4.8**
со ссылками на DLL этой установки. Обновление Autodesk Revit не требуется и не выполняется.
Версия плагина и MCP-сервера — **2.2.0**; устанавливать обе части вместе.

## Исправления

- Границы помещений/зон, шахты и редактирование формы плит используют проектные
  отметки `Level.ProjectElevation`. Отметки относительно общей системы координат
  не подставляются в API, ожидающий координаты проекта.
- Сила опорной плоскости семейства задаётся через встроенный параметр
  `ELEM_REFERENCE_NAME`, без английского имени `Is Reference`.
- Запись параметров в исправленных обработчиках использует однозначное разрешение:
  встроенный идентификатор, GUID, `id:<64-bit id>` или уникальное имя. Совпадающие
  имена не выбираются произвольно; параметр типа не изменяется вместо параметра экземпляра.
- Исправлено редактирование только физических/тепловых свойств материала.
  `class`, `material_type` и `name` обрабатываются как метаданные, а не числа.
  Величины принимаются как `{ "value": 2400, "unit": "KilogramsPerCubicMeter" }`;
  проверяется соответствие единицы физической величине. Число без объекта сохраняет
  прежнее значение во внутренних единицах Revit.
- Общие активы материалов копируются только по явному `duplicate_shared_assets=true`.
  В Revit RTM `SetStructuralAsset` отказывает, если имя занято тем же property set.
  Имя временно освобождается внутри транзакции и восстанавливается setter-ом;
  идентификатор существующего актива сохраняется. Копии получают уникальные имена.
- Предварительный просмотр материалов выполняет реальное изменение с откатом.
  После записи повторно проверяются запрошенные графические, физические,
  тепловые и визуальные свойства. Изменение зависимостей делает подтверждение устаревшим.
- CAD/IFC-происхождение проверяется после завершения транзакции. Ошибка метаданных
  не считается полной успешной конвертацией; ответ сохраняет сведения об уже
  созданной геометрии. Пустые строки нормализуются согласно формату Extensible Storage.
- Для рецептов и новых операций подтверждение учитывает идентичности элементов,
  версии и события изменения документа. Один `VersionGuid` не выявляет все
  изменения между сохранениями. Откат собственного предварительного просмотра
  учитывается до выдачи токена.
- Читающие команды принимают полный нормализованный путь активного документа.
  Другой путь с тем же именем файла не проходит проверку.
- Хеш подтверждения новых операций не зависит от порядка полей JSON. Изменение
  геометрии или других значимых значений по-прежнему требует нового просмотра.
  Составной план передаёт служебный отпечаток только обработчикам, которые его проверяют.
- Для линейных семейств уровень проверяется также через `FamilyInstance.Host`:
  в RTM он может быть задан при `LevelId=-1`. Ячейки заголовка спецификации щита
  отклоняются до попытки переноса цепи, даже если `CanMoveSlotTo` вернул `true`.
- Устранено квадратичное замедление проверки текстового ответа: доверенные
  служебные поля вычисляются один раз, а не через `JToken.Path` для каждой строки.

## Новые операции

`horizun_revit2024` предоставляет следующий закрытый набор операций. Любое поле,
не применимое к выбранной операции, отклоняется. Записи используют обычные
`target_document`, `dry_run`, `confirmation_token` и `idempotency_key`.

| Область | Операции |
|---|---|
| Диагностика | `catalog`, `appearance_read` |
| Топотела | `site_create`, `site_subdivide`, `site_convert` |
| Аналитическая модель | `analytical_member_create/edit`, `analytical_panel_create/edit`, `analytical_associate` |
| Нагрузки | `analytical_point_load`, `analytical_line_load`, `analytical_area_load` |
| Fabrication | `fabrication_load_service`, `fabrication_create`, `fabrication_convert` |
| Электрика | `wire_create`, `circuit_set_path`, `panel_move_slot` |
| Семейства | `family_curve`, `family_adaptive` |

Точные поля опубликованы в MCP-ресурсе `horizun://contract/tools/horizun_revit2024`.
`catalog` выдаёт идентификаторы типов, уровней и сервисов Fabrication. Геометрические
единицы: `mm`, `m`, `feet`. Силы и моменты требуют отдельной явной единицы.
Для дуги передаются начало, конец и точка на дуге; границы — замкнутые многоугольники.
Провода создаются как неподключённая геометрия на указанном виде. Адаптивное семейство
требует точного числа точек размещения. Fabrication требует конфигурации проекта,
загруженных сервисов и совместимых деталей; частичная конвертация откатывается.

В `horizun_manage_materials` добавлен `appearance_properties`: список объектов
`path`/`value`. Поддерживаются существующие строковые, логические, целочисленные,
числовые свойства и цветовые массивы из четырёх компонент. Путь с `/` проходит
по существующим подключённым активам, например к пути изображения текстуры.
Новые графы шейдеров этот обработчик не создаёт.

## Проверка и границы покрытия

`horizun_health` с `include_capabilities=true` возвращает реестр операций,
версию хоста, наличие необходимых API-типов, зависимости и наблюдавшиеся успешные
сценарии этой сессии. Наличие метода в API, наличие реализации и успешное испытание
— разные факты. Один успешный вызов не доказывает все шаблоны и входные данные.

`scripts/export-installed-api-inventory.ps1 -OutputDirectory <каталог>` экспортирует
реестр из XML-документации именно установленного Revit, версии и SHA-256 его DLL.
Для 24.0.4.427 реестр содержит 30 660 членов RevitAPI и 2 557 членов RevitAPIUI.
Он не объявляет каждый член отдельным доступным MCP-инструментом.

Воспроизводимые испытания: собрать `src/Horizun.Revit` с `-p:RevitYear=2024`,
затем `tests/Horizun.Revit2024.Live`; запустить
`scripts/live/run-installed-2024-audit.ps1 -Language RUS -RunRoot <новый каталог>`.
Параметр `-ProbeServer <свежий horizun-mcp.exe>` дополнительно проверяет настоящий
MCP-транспорт: health, каталог, просмотр, запись и повтор с тем же ключом идемпотентности.
Для английского интерфейса использовать `-Language ENU`; `-UseInstalled` загружает
надстройку из фактического установленного каталога.
Стенд требует закрытого Revit, создаёт собственные проекты из установленных
шаблонов, сохраняет запросы и ответы, восстанавливает исходный манифест после
нормального завершения. Окно доверия неподписанной DLL подтверждает пользователь.
Пользовательские проекты стенд не открывает.

### Измеренный результат от 8 октября 2026 года

Это результаты локальной проверки до публикации изменений. SHA-256 в
`revit-2024-implementation.json` относятся к той сборке. Финальную сборку из
чистого коммита `main` следует проверять отдельно: её отчёт должен фиксировать
этот коммит, `built_from_clean_tree=true` и хеши фактически загруженных файлов.

- **5 851 тест ядра и 1 054 теста сервера прошли**, всего 6 905, без пропусков.
  Тесты выполнены на .NET 8.0.31; установленный автономный сервер содержит
  зафиксированный в проекте runtime 8.0.30 и отдельно прошёл живой MCP-тест.
- **36 сценариев прошли в RUS и 36 в ENU** на одном Revit `24.0.4.427`.
  В ENU загружалась именно установленная `Horizun.Revit.dll`, что подтверждено
  её путём и SHA-256 в `horizun_health`, а не только проверкой файла на диске.
- Один дополнительный сценарий в каждом запуске имеет статус
  `unavailable_dependency`: **на машине нет конфигураций Fabrication**.
  Три операции Fabrication скомпилированы, но успешное создание/преобразование
  деталей без базы и сервисов не проверено. Для их приёмки нужен отдельный
  тестовый проект с совместимой конфигурацией; обновление Revit для этого не требуется.
- Настоящий MCP-цикл `dry_run → apply → replay` прошёл в обоих запусках.
  При replay возвращается прежний `element_id`,
  `idempotency.command_executed_in_this_call=false`.
- Установлены обе части версии **2.2.0**, их контракт совпадает:
  `ffa79adb4e9bb4e4c6050158`. В каталоге — **124 инструмента**, 478 вариантов
  диспетчеризации; эти числа описывают интерфейс, а не количество живых тестов.

Артефакты находятся рядом с репозиторием, в `../audit-revit-2024/`:
`core-net8-release220-accepted.trx`, `server-net8-release220.trx`,
`live-rtm-rus-08/`, `live-installed-rtm-enu-09/`, `installed-payload-220.json`.
В каталогах живых тестов сохранены запросы/ответы, модели, `report.json`,
MCP health/preview/apply/replay и параметры запуска. Резервная копия до установки —
`before-install-220/`. Эти артефакты находятся вне Git и не входят в исходный код.

Тестовые сессии Revit закрыты. После перезапуска Codex он перечитает каталог
инструментов новой сборки; отложенный помощник установщика завершит регистрацию
при закрытии клиента. Текущий путь сервера из конфигурации уже проверен.

Результаты испытаний и незакрытые зависимости фиксируются отдельно в
`revit-2024-implementation.json`. Нельзя трактовать этот выпуск как автоматизацию
каждой кнопки Revit: часть UI не имеет синхронного публичного API, а внешние
экспортёры, библиотеки Fabrication, права совместной работы и семейства остаются
зависимостями конкретного проекта. Встроенный `WriteVerificationCatalog` продолжает
перечислять известные ограничения остальных существующих обработчиков.
