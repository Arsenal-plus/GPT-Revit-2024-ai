# Надёжное выполнение задач в Revit 2024

Версия 2.3.0 рассчитана на установленный Revit **24.0.4.427**. Обновление Revit не требуется.
Результаты испытаний приведены в отдельном отчёте после завершения проверки.

## Почему появлялся Failed

Полные разрешения не обеспечивают правильный контекст API. Команда семейства требует
документ RFA, запись элементов — указанный активный проект. Снимок вида обязан вернуть
камеру и временные настройки. Геометрические проверки должны учитывать проекцию
проёма на стену и допустимую погрешность чисел. Пустые границы помещений и отсутствие
BoundaryRect у непрямоугольных проёмов являются допустимыми состояниями API.

## Последовательность с подготовкой документов

`horizun_run_workflow` принимает `target_document` и от 1 до 20 шагов
`{key, tool, arguments}`. Доступны только перечисленные в контракте типовые команды.
Python, рекурсивные workflow, закрытие документов и обновление файлов при открытии
не входят в этот механизм.

Предварительный вызов связывает подтверждение с точными шагами и состоянием всех
открытых документов. Он **не является репетицией построения будущих шагов**.
При применении каждый изменяющий шаг проходит собственную предварительную проверку,
применение и проверку результата. Ссылки вида `${make.rows.0.element_id}` передают
результаты предыдущих шагов. Права каждого дочернего инструмента проверяются отдельно.

Указанный по пути документ открывается или активируется перед шагом. Автоматического
сохранения пользовательских документов нет. Для неактивного несохранённого документа
нужно сначала выбрать его в Revit. Неоднозначное имя не заменяется похожим именем.
Если права или исходные данные не позволяют продолжить, выполнение останавливается.

Все шаги занимают один вызов UI Revit, поэтому другой MCP-клиент не может вставить
команду между ними. Это не транзакция сразу над несколькими файлами:
при ошибке второго шага результат первого сохраняется и явно указывается.

## Повторы и журнал

Для применения обязательны `confirmation_token` и `idempotency_key`.
Повтор того же запроса с тем же ключом возвращает сохранённый ответ, включая ошибку.
Ключ нельзя менять ради повторного выполнения неопределённого изменения.
После потери процесса незавершённая запись остаётся неопределённой и не запускается
автоматически: сначала нужно осмотреть модель.

`trace_path` указывает на UTF-8 JSONL в `%USERPROFILE%\.horizun\workflows`.
Начало и результат каждого шага сбрасываются на диск перед следующим действием.
Эти журналы содержат данные модели и хранятся локально без автоматического удаления.
Обычные квитанции содержат структурированную причину отказа и способ подготовки.

Панель различает подготовку, подтверждённый откат, непроверенный результат,
частичное выполнение и проверенное завершение. Старые записи не переписываются.
`Success=true` транспорта само по себе не означает полное применение изменений.

## Снимок данных и Python

`horizun_model_snapshot` читает заданные ID: категорию, тип, положение, габариты,
хозяина семейства/проёма, прямоугольные или криволинейные границы проёма и границы
помещения. Длины — миллиметры, координаты — относительно внутреннего начала,
ID — 64-битные. `complete` относится к полноте чтения запрошенных элементов;
доступность конкретной геометрии отражается отдельными статусами.
Обрезка слишком большого ответа и отсутствующие ID не выдаются за полное чтение.

В Python доступны `read_json(path)` (UTF-8 с необязательным BOM) и
`optional_items(value)`. Второй помощник заменяет None пустой коллекцией только
для безопасного обхода; вызывающий код по-прежнему должен отметить отсутствие данных.
Кодировка входного файла должна быть известна: файлы Windows-1251 требуют её
явного указания. Результаты Python остаются свидетельством самого сценария.

## Границы исправлений

Неверная геометрия, недостаточные исходные данные, заблокированные элементы,
несовместимые семейства и запреты пользователя остаются обоснованными отказами.
Успешным считается измеренный результат, а не исчезновение слова Failed.
Камера сравнивается с допуском 0.000001 фута по координатам и 0.000000001
по направлениям; флаги и идентификаторы сравниваются точно.
Неуказанный `primary` коннектора означает выбор Revit; явно заданный флаг проверяется.
